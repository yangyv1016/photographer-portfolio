# 订阅、兑换码与容量

订阅功能同时适用于本地存储和 COS 存储。兑换只更新平台数据库中的权限、期限和容量，不迁移作品目录，也不更换账户 UUID。

## 套餐规则

| 套餐 | 价格 | 固定有效期 | 当前总存储额度 |
| --- | ---: | ---: | ---: |
| 月卡 | ¥8 | 30 天 | 5 GiB |
| 季卡 | ¥20 | 90 天 | 10 GiB |
| 年卡 | ¥88 | 365 天 | 20 GiB |

容量沿用项目的二进制计量：1 GiB = 1024³ 字节。照片、头像、两种封面和未完成上传均计入已用容量。

每个订阅兑换码包含发行时保存的套餐、有效天数和容量。码的“可兑换有效期”控制它最晚何时可以使用，与兑换后获得的订阅天数是两个独立设置。

## 生成与使用兑换码

管理员在工作台的兑换码管理中选择套餐模板、数量、码有效期和备注。选择模板会预填订阅天数和存储总额度，两项均可在生成前单独调整；本次发出的码保存实际填写的权益，不改变公开套餐或爱发电自动发货的默认权益。例如，以月卡为模板生成 45 天、8 GiB 的码，注册或续期时得到的就是 45 天和 8 GiB。

“订阅天数”从成功注册或兑换时计算；“可兑换期限”控制码最晚何时可用。手动生成的完整码仅在生成时显示，请立即复制或下载保存；数据库保留哈希及使用记录，不提供恢复完整码的接口。爱发电自动发货另存加密副本，用于发送失败后重试同一个码，见下文。

同一个码可以用于以下任一场景，每个码只能成功使用一次：

- 新用户在注册页填写邀请码／兑换码，注册成功时激活相应订阅。
- 老用户进入「订阅与容量」，输入兑换码，先预览套餐、容量及新到期时间，确认后续期。

续期后的到期时间为 `max(当前时间, 原到期时间) + 新卡固定天数`。跨套餐兑换时容量立即切换为新卡总额度，不累加。

例如，年卡用户尚未到期时兑换月卡，订阅期限在原到期时间后增加 30 天，容量立即切换为 5 GiB。如果已用容量超过 5 GiB，已有作品保留，需释放空间或兑换更高容量套餐后才能继续上传。确认页面会展示这个变化。

码的消费、订阅更新和兑换记录在同一 SQLite 事务中完成。刷新页面、重复提交或并发请求不会把同一个码兑换多次。

## 管理员配置账户

「账户管理」中的「账户配置」可一次保存账户的套餐、订阅到期时间和容量总额度。打开时显示账户当前值；选择套餐模板会预填该档容量和从当前时间计算的到期时间，保存前仍可修改。到期时间按北京时间输入。

这里是管理员直接设置到期日，覆盖账户的原到期时间；用户用码续期仍按上面的规则追加天数。选择「长期有效」时清除套餐和到期限制，容量仍按填写值执行。管理员账号本身免订阅，只可调整容量。

配置不会修改用户的主入口展示选择、登录状态或作品存储 UUID。下调容量、设为到期或长期有效都不会删除照片；超额与到期后的行为沿用下文规则。套餐或到期时间实际改变后，会清除已有到期提醒标记；仅修改容量不会重置提醒。

## 到期与提醒

订阅截止前 7 天，工作台顶部显示提示，并在每天首次进入时弹窗提醒。是否已经提醒由服务器记录，按北京时间的日期判断，多个标签页或浏览器不会重复领取同一天的提醒。

到期后：

- 公开主页和相册显示“本用户订阅已到期，请及时订阅”。
- 公开目录不继续展示该账户；公开媒体接口不再提供原图、缩略图、头像或封面。
- 照片及资料图片暂停上传，包括恢复分块和完成未结束的上传。
- 仍可登录工作台、兑换续期、管理及删除自己的内容、取消未完成任务和下载自己的原图。
- 文件和数据库保留，不自动删除，不把订阅到期改成管理员停用。

兑换有效订阅后恢复公开展示及上传；上传仍受当前套餐总额度约束。

## 升级已有部署

安装新版时自动追加订阅字段和兑换记录表。已有账户保持原来的长期权限，旧邀请码继续沿用既有注册规则；管理员免订阅。新发出的套餐码按上表执行。

长期账户主动兑换套餐码后会转为该套餐的有限期订阅，因此也必须经过兑换预览与确认。管理员不能消费订阅码，避免误用。

数据库快照包含订阅、兑换记录和每日提醒状态；原图仍须按所选存储方式单独备份。

## 爱发电对接范围

网站侧生成、注册和后台兑换不依赖爱发电认证，也不要求配置 API Token。完整码可先由管理员分发。

爱发电认证完成后，应把月、季、年三个独立方案的 `plan_id` 分别对应到本站套餐。API Token 仅保存在服务器的凭据配置中，不放入浏览器、源码或兑换码文本。

当前站内订阅期限为固定 30／90／365 天，不直接套用爱发电站内权益的日期计算。不能仅凭页面跳转或前端金额激活权益。

爱发电接口说明见[官方 API 文档](https://ifdian.net/p/9c65d9cc617011ed81c352540025c377)。

## 固定链接自助发货

固定入口是 `https://你的域名/claim`，不依赖 Webhook。可把链接放入爱发电方案说明和普通自动回复中；买家无需先注册本站账号。

1. 买家从爱发电订单详情复制订单号，在领取页提交。
2. 服务器通过签名请求 `query-order` 查询该创作者的真实订单，核对已支付状态、方案、购买月份及实际支付金额。
3. 通过后生成兑换码，通过 `send-msg` 仅发给订单 API 返回的原买家账号。领取页只显示处理状态，不返回兑换码、买家 ID 或私信内容。
4. 买家在爱发电私信取码，用于本站注册或在「订阅与容量」中确认续期。

服务器环境配置以下可选变量；全部配置完整才会开放领取表单。未配置时不影响手动发码、订阅及存储。API Token 和加密密钥不得放在前端或提交到 Git。

```dotenv
AFDIAN_USER_ID=你的创作者user_id
AFDIAN_API_TOKEN=你的API_Token
AFDIAN_DELIVERY_KEY=64位十六进制随机密钥
AFDIAN_MONTHLY_PLAN_ID=月卡方案plan_id
AFDIAN_QUARTERLY_PLAN_ID=季卡方案plan_id
AFDIAN_YEARLY_PLAN_ID=年卡方案plan_id
```

可用 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 在管理员终端生成加密密钥。只在首次部署生成，更新时保留原值。配置文件应限制为管理员可读，并与数据库分别保密备份；丢失密钥后，数据库中的自动发货码不能解密重试。

方案对应周期为 1／3／12 个月，每期价格必须是 ¥8／¥20／¥88。多期订单的天数是对应固定天数乘期数，容量仍为该档总额度。例如购买两期季卡，得到一个 180 天、10 GiB 的兑换码。校验使用订单的实际 `total_amount`，不把方案 API 的基础月价格误作季卡或年卡总价。不支持的方案、非完整周期、赠送／兑换订单或金额不匹配需要人工处理。

首次发码前还会查询 `query-random-reply`：已有非空随机回复的订单停止发码，避免与旧库存码重复发货；历史查询失败时也不发新码。切换后请使用普通自动回复提供领取链接，不要同时为同一批订单启用随机库存码发货。以前人工私信或其他系统发过的码需要管理员核对，本系统不能自动识别所有外部发货记录。

订单号是唯一键。发码与订单关联在同一数据库事务中写入，发送采用带期限的互斥租约，刷新及并发提交不会生成第二个码。发送失败需至少等待 60 秒再重试，继续发送原码；原码已使用则不再发送，已撤销或过期则转人工处理。若平台已收到私信但接口响应丢失，重试可能收到同一码的重复私信。已确认发送的订单不重复发送。

自动发货码以 AES-256-GCM 加密保存，注册及续期仍只根据哈希核销，不提供公开解密接口。领取接口按每来源每分钟 5 次、服务进程每分钟 15 次限流，并要求同源提交。当前部署为单 Node 进程，限流为进程内状态；不要在未增加共享限流前扩展为多实例。

`GET /api/integrations/afdian/delivery/status` 仅返回配置是否齐全，不表示创作者账号已获得私信权限。上线需用真实付款订单验收发货权限。退款暂不自动撤销已发的码或已兑换的订阅，需人工处理。

## Webhook 连通测试

可在爱发电开发者后台的 Webhook URL 填写：

```text
https://你的域名/api/integrations/afdian/webhook
```

保存后使用爱发电的“发送测试”。接收端接受标准订单 JSON，成功持久保存后返回 `ec: 200`、`mode: "test"` 和 `auto_fulfillment: false`。

当前为测试收件模式：所有通知均标记 `pending_verification`，不视为已核验付款，不生成或消费兑换码，不修改订阅期限和容量。开发者后台显示发送成功只表示通知送达，不代表完成了发码。

仅管理员可通过 `GET /api/platform/afdian/receipts` 分页查看最小收件记录。保存订单号、买家标识、方案、月份、金额、订单状态、收件时间和重复次数；不保存签名、地址、电话号码、留言或完整请求体。重复订单只更新收件次数和最后接收时间，不能覆盖首次保存的字段。

测试入口按每来源每分钟 30 次、服务进程每分钟 120 次限流。最多保留 5000 个不同订单的测试记录，达到上限会拒绝新订单并返回 503，已有通知仍可更新重复次数；不会自动删除记录。

自助领取使用上述独立订单核验流程；Webhook 仍只收测试记录，不触发发码。不要把当前测试收件成功当作付款验证结果。
